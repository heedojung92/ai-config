# 코드·구성 리뷰

## 범위

- 리뷰 대상이 commit 간 diff, staged 변경, 작업 트리 중 무엇인지 고정한다. 기준 ref와 미커밋 변경 포함 여부를 기록한다.
- 변경 파일을 읽고 영향을 받는 호출자, 타입·스키마, 테스트, 배포·실행 구성을 따라간다. 읽지 않은 범위를 전체 안전으로 일반화하지 않는다.
- 리뷰만 요청받았으면 코드를 임의로 수정하지 않는다. 수정까지 요청받았다면 발견과 수정·검증을 구분한다.

## 우선 확인

- 요구·계약 위반, 기본값·null·경계값, 예외 처리, 자원 해제, 상태 전이.
- API·직렬화·스키마 호환성, 다른 호출자·소비자에 대한 회귀.
- 경쟁 상태, 재시도·중복 처리, 취소·timeout·부분 실패.
- 실제 영향이 있는 성능·자원 문제와 불필요한 원격·DB 호출.
- 권한·비밀 노출·입력 처리와 기술적 보안 경계.
- 모듈 책임, 의존성 방향, 과도한 결합, 잘못 놓인 상태·추상화.
- 테스트가 실제 실패를 구분하는지와 필요한 입력·분기를 놓쳤는지.

플랫폼·IaC 변경에는 플랫폼 가이드의 관련 절을 추가한다. 모든 리뷰에 모든 분야의 전수 검사를 강제하지 않는다.

## 발견 사항의 형식

각 발견에는 문제, 발생 조건, 영향, 근거 위치, 수정 또는 검증 방향을 포함한다. 같은 원인의 여러 증상은 묶는다.

- 위치: 실제 파일과 관련 줄.
- 조건: 어떤 입력·상태·실행 순서에서 발생하는가.
- 영향: 어떤 계약이 깨지거나 어떤 소비자가 실패하는가.
- 근거: 실제 소스·관측·재현 또는 명시한 추론.
- 조치: 문제가 닫혔는지 확인할 변경·시험.

확인된 결함과 아직 확인할 질문을 구분한다. 가능성만으로 확정 결함처럼 쓰지 않는다. 요청하지 않은 스타일 취향·사소한 이름 바꾸기를 결함 목록에 채우지 않는다.

발견이 없으면 읽은 범위와 남은 검증 경계를 말한다. 모든 환경에서 결함이 없다고 보증하지 않는다. 리뷰어 동의나 자동 검사 통과만으로 실제 동작의 정확성을 확정하지 않는다.
