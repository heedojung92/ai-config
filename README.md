# Engineering Workspace

개발, 코드 구조 검토, 코드 리뷰, 데이터 플랫폼, Kubernetes, 인프라 작업을 위한 저장소다.

## 시작

1. 작업 목표와 대상 프로젝트를 정한다.
2. 공통 지침은 [AGENTS.md](AGENTS.md)를 따른다.
3. 작업에 필요한 가이드만 읽는다.

| 작업 | 가이드 |
|---|---|
| 구현·디버깅·리팩터링·설계 | [개발](guides/development.md) |
| 코드·구성 변경 리뷰 | [리뷰](guides/review.md) |
| 데이터 플랫폼·K8s·인프라 | [플랫폼](guides/platform.md) |

## 프로젝트

실제 작업이 생기면 `projects/<project-name>/`을 만든다. 각 프로젝트의 README에서 목적, 코드·구성 위치, 환경, 검증 명령을 안내한다. 언어·도구의 기존 디렉터리 관용을 사용한다.

현재 프로젝트가 없으면 공통 검증 명령도 없다. 빈 검사기를 만들어 성공을 출력하지 않는다.

별도 저장소의 코드를 다룰 때는 그 저장소를 직접 대상으로 작업하고 복제된 소스 사본을 이곳에 쌓지 않는다.

## 검증과 기록

검증은 프로젝트가 사용하는 빌드·린트·테스트·렌더링·정적 분석·CI로 수행한다. 공통 검사 프레임워크나 자동 hook은 기본 설치하지 않는다.

작은 작업은 변경과 검증 결과를 보고한다. 세션을 넘기는 작업만 해당 프로젝트의 `NOTES.md`에 목표, 결정, 확인 결과, 미확인, 다음 행동을 남긴다.
