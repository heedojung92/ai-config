# 지침 개선 회고

1. 이 세션에서 다음을 찾고 각 항목에 근거(어느 요청·명령·출력)를 붙인다: 사용자가 바로잡은 행동, 같은 실수의 반복, 검사 실패의 원인, 매번 다시 알아내야 했던 사실, 위험할 뻔한 행동.
2. 한 번뿐인 실수, 저장소를 읽으면 알 수 있는 사실, 모델이 다음에 스스로 피할 실수는 버린다. 남은 항목은 갈 곳을 정한다.

   | 종류 | 위치 |
   |---|---|
   | 프로젝트 명령·환경·함정 | `projects/<name>/AGENTS.md` |
   | dbt·Airflow·Kotlin·K8s 파일의 함정 | `.claude/rules/<도메인>.md` |
   | 모든 작업에 해당하는 행동 규칙 | `AGENTS.md`(드물게) |
   | 비밀 파일 읽기처럼 도구가 막아야 하는 것 | 비밀 파일이면 `.claude/settings.json` deny, 그 밖은 프로젝트 hook·CI 제안 |
   | Claude Code 기능 사용 | `CLAUDE.md` |
   | 작업 종류별 판단 기준(도구 공통) | `guides/*.md` |
   | 반복되는 여러 단계 절차 | `.claude/skills/<이름>/` |
   | 도구로 잡을 수 있는 실수 | 프로젝트 linter·테스트·CI |

3. 각 안은 규칙 한 줄과 이유, 바뀔 파일의 diff로 쓴다. 기존 줄과 겹치거나 충돌하면 새 줄을 더하지 말고 기존 줄을 고치거나 지우는 안을 낸다. IMPORTANT·MUST 같은 강조어는 쓰지 않는다.
4. 사용자가 고른 안만 반영한다. 반영한 커밋 메시지에는 계기가 된 실패를 적는다. commit은 사용자가 요청했을 때만 한다.
